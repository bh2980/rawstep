# Rawstep 화면 기반 탐색과 VoiceOver 근거 보강

> Historical snapshot. The current seven-workspace delivery and its validation limits are recorded in [V5 completion](./completion-v5.ko.md).
Rawstep에 실제 스크린샷을 보고 키보드 행동을 선택하는 실행 모드를 추가하고, 공개된 VoiceOver 실행 결과를 수집해 시뮬레이터의 일부 발화 규칙을 수정했습니다. 실행 경로와 근거 수집은 검증했지만, 작은 모델의 일반 웹 탐색 성능이나 실제 VoiceOver와의 동등성까지 입증한 것은 아닙니다.

## 화면 기반 키보드 실행

`screenshot-run` CLI와 `rawstep/screenshot` API를 추가했습니다. 실행 순서는 실제 Chromium 화면 PNG → 모델의 선택지 평가 → 키보드 입력 → 새 화면 관찰입니다.

- 정책 입력은 화면 픽셀, 목표, 허용 행동, 제한된 행동 이력입니다. DOM·접근성 트리·선택자·OCR 문자열·독립 검증 결과를 넘기지 않습니다.
- 행동은 키보드 입력과 사용자가 제공한 이름 있는 입력값으로 제한합니다. 마우스 클릭이나 DOM 포커스 지정으로 행동을 대신하지 않습니다.
- 모델 실패나 잘못된 선택을 정해진 행동 스크립트로 바꾸지 않습니다. 반복 화면·최대 단계·시간 제한으로 중단하고 실패 근거를 기록합니다.
- 화면 변화, 행동 전후 연결, 모델 선택 근거를 trace와 보고서에 남깁니다. 실제 포커스 위치를 화면만으로 확정할 수 없는 경우 불확실성도 유지합니다.
- 로컬 모델 엔드포인트가 기본입니다. 원격 전송은 명시적 허용이 필요하고, 입력 후 저장되는 화면·진단은 기본 개인정보 보호 규칙을 따릅니다.

기존 실행 예산, 취소, 탐색 제한, 입력 가능 여부 검사, 독립 성공 판정과 기록 실패 시 중단 처리는 유지했습니다. 화면 모델의 자신감이나 성공 선언만으로 작업을 성공 처리하지 않습니다.

## 실제 OneJev 모델 검증

별도 실험 예제에는 공개된 [OneJev 0.8B](https://huggingface.co/OmniJev/OneJev-0.8B) 가중치를 사용했습니다. 고정한 모델 버전과 표준 Transformers 런타임으로 실행하며, 원격 모델 코드는 실행하지 않습니다. 선택지 토큰의 logits를 한 번의 forward pass로 평가하는 방식입니다. TypeSafe의 비공개 Jev와 같은 모델이라고 주장하지 않습니다.

일반 키보드 탐색 예제는 성공하지 못했습니다. 기본 지시와 일반적인 키보드 탐색 안내를 추가한 두 실행 모두 모델이 `Enter`를 4회 반복했고, 화면이 하나의 상태에 머물렀습니다. 5번째 단계에서 독립적인 반복 방지 장치가 실행을 실패로 중단했습니다. 모델이 스스로 막힘을 올바르게 판단한 결과로 계산하지 않았습니다.

이와 별도로 다음 버튼에 자동 포커스가 주어지는 쉬운 2단계 예제에서는 실제 모델 추론 2회와 스크린샷 3장으로 연결 경로를 확인했습니다. 이 성공은 모델·화면·행동·기록의 연결 검증이며, 자연스러운 포커스 탐색 능력을 입증하는 점수로 사용하지 않습니다. 픽셀 변경 실험에서 모델의 선택이 달라졌다는 결과 역시 이미지 사용의 근거일 뿐, 선택이 옳다는 근거는 아닙니다.

최종 소스 재실행에서도 동일한 쉬운 예제 성공과 일반 탐색 실패를 재확인했습니다. 측정된 0.8B 모델 추론은 1회 약 4.3~7.2초였으며, 스크린샷 해시 → 모델 점수 → argmax 선택 → 실제 키 입력 → 새 화면의 연결을 별도 감사로 확인했습니다. 이 시간은 해당 클라우드 실행의 측정값입니다.

모델 가중치와 Python 런타임은 코어 npm 의존성에 넣지 않았습니다. 재현용 실험 파일은 별도 묶음으로 제공합니다.

2026-10-01 16:50 UTC 코어 패키지 검증 시점에, 사용자가 요청한 더 큰 4B 양자화 모델의 동일 예제·동일 선택지 비교는 별도 실험으로 진행 중입니다. 위 결과와 검사 수치는 완료된 코어 및 OneJev 0.8B 실행에 대한 것이며, 4B의 성능을 미리 가정하지 않습니다.

## VoiceOver 실행 결과 수집과 적용

[Accessibility Supported](https://a11ysupport.io/)에서 548개 명령 결과, [ARIA-AT](https://aria-at.w3.org/reports)에서 742개 시나리오 결과를 수집했습니다. 합계 1,290개는 제3자가 보고한 테스트 결과 레코드이며, 모두 깨끗한 녹음 전사이거나 이번에 새로 측정한 발화라는 뜻은 아닙니다.

레코드에는 원문 출력, 행동, 포커스 전후 조건, 보고된 AT·브라우저·OS 버전, 테스트 날짜, 원본 링크·해시·저작권 표시를 보존했습니다. 알려지지 않은 Quick Nav·발화 상세도·음성 등의 설정은 알 수 없음으로 남겼습니다. 예상 ARIA 요구사항을 실제 관측값으로 바꾸어 저장하지 않았습니다.

수집 근거로 다음과 같은 제한된 탐색 발화를 수정했습니다.

- 토글 버튼의 `toggle button`, `selected`, `mixed` 표현
- 체크박스와 펼침 버튼의 상태·역할 순서
- 일반 링크의 역할·이름 순서
- 빈 텍스트 필드의 `edit text`, `required` 위치와 textarea의 이름·역할·값 순서

선별한 13개 탐색 문구 비교에서 일치하는 사례가 **2개에서 13개로 증가**했습니다. 대소문자·공백·쉼표·마침표를 제외하고 단어와 순서를 비교한 결과입니다. 전체 코퍼스에 대한 정확도나 네이티브 VoiceOver 적합성 점수는 아닙니다.

프로필은 `english-dom-navigation-evidence-v2`로 구분했습니다. 서로 다른 버전의 근거를 참고한 복합 시뮬레이션이며, 런타임 출력은 계속 `simulation`으로 표시합니다. 활성화 직후 발화, 선택 영역, 힌트, 발화 큐와 타이밍은 이 수정으로 검증되지 않았습니다.

자료의 한계도 함께 남겼습니다. ARIA-AT에는 무발화 표시 25개, 테스트 불가 40개, 테스트 도구 화면이 섞인 것으로 표시한 결과 1개가 포함되어 있습니다. 470개는 기록 종료 시점이 현재 시작 시점보다 빨라 과거 결과의 이월 가능성이 있습니다. 대부분 후보 보고서이며 공급자 승인과 동일하지 않습니다. 자료 묶음에는 출처별 라이선스와 재배포 유의사항을 보존했습니다.

## 최종 검사

- 전체 **461개 테스트, 26개 파일 통과**, skip 없음
- 실제 Chromium 통합 검사는 기존 97개와 새 화면 모드 9개를 합쳐 **106개 통과**
- 빌드와 소스·테스트 TypeScript 검사 통과
- 저장소 밖 npm 설치본에서 공개 API 14개와 실제 Chromium 기반 `screenshot-run` 검증 통과
- 설치본의 로컬 HTTP 테스트 모델 왕복 2회와 simulation CLI 검증 통과. HTTP 테스트 모델은 실제 OneJev 평가와 구분
- SIGINT 종료 코드 130, SIGTERM 종료 코드 143, journal 기록 실패 시 중단 보호 검증 통과
- 독립 코드 검토 완료

VoiceOver 보강 부분의 별도 확인에서는 실제 Chromium 통합 테스트를 포함한 4개 관련 테스트 파일의 38개 검사가 통과했습니다. 브라우저 sandbox를 켠 검증된 Chromium 런타임을 사용했습니다. 사용자 Mac과 실제 VoiceOver는 사용하지 않았습니다.

## 전달물과 재현 안내

- 갱신된 소스, 패치, npm 패키지와 이 보고서
- 출처·버전·품질 표시·검증 스크립트를 포함한 VoiceOver 자료 묶음
- 실제 OneJev 모델 실험과 측정 결과 묶음

사용법은 `docs/screenshot-keyboard.md`, 화면 실행 측정은 `docs/screenshot-verification.md`, VoiceOver 근거와 적용 범위는 `docs/mock-voiceover-evidence.md`에 정리했습니다.
