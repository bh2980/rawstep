# Historical test migration accounting

Baseline: `d567466074b99d9e2580a6da8fed7ab3ededdf3f`. The old source graph contained **329 tests in 15 suites**. Those suites were reviewed before removing their imports and workspace implementation. This is not a claim that deleting failing tests fixes behavior: retained responsibilities were first ported to a single implementation graph and new native/DOM/protocol boundaries; that implementation now lives in the physical package workspaces; tests whose subject no longer exists are explicitly retired below.

Classification: **167 ported/reworked**, **162 retired**. “Reworked” means preserving the relevant responsibility under the new contracts, not preserving obsolete wire syntax, exact error wording, cost counters or report HTML. Some original tests span both retained safety checks and deliberately removed features; the note states that distinction. New tests can cover several old cases, or split one old case into several narrower checks. Counts are therefore not one-to-one.

## Browser failures are not excluded

The previously reported 77 browser-dependent failures came from an unusable local Chromium executable. The original fixture HTML and HTTP navigation fixture scripts are retained. Mandatory real Chromium suites now exercise:

- `verifier-browser.integration.test.ts`: 12 original browser verifier cases, covering CTA/search/bad-focus state, DOM events, title/URL/text, network rules, collected activation evidence, and empty/malformed login forms
- `keyboard-browser.integration.test.ts`: real Tab/Enter fixture completion, stuck outcomes, named email/password/search inputs, persisted trace/privacy, screenshot history, actual focused text/textarea/contenteditable gates, readonly/disabled/non-text rejection, and destructive replace behavior
- `navigation-browser.integration.test.ts`: 14 retained HTTP cases covering same-origin, prefixes, allow lists, popups, forms, relative links/forms, service-worker attempts, `window.location.assign`/`replace`, and continued use of allowed controls
- Additional CDP/redirect integration tests cover initial and later redirect hops, cookies, method/body semantics, external-side-effect prevention and fail-closed conditions

Removed Guidepup synthetic-output/startup-repair branches are not recreated to inflate a legacy browser-test count. Exact per-case disposition is listed below. Browser integration is separate from native screen-reader certification: no VoiceOver or NVDA desktop session was run. jsdom unit suites execute actual fixture and injected guard scripts as supplementary fast coverage, and explicitly do not claim native browser/layout/AT behavior.

## Reproduction and aggregate scope

```sh
pnpm install --frozen-lockfile
npx playwright install chromium
npm run check
# Narrow mandatory real-browser suite:
npm run test:integration
# For a trusted compatible custom Chromium executable:
RAWSTEP_TEST_BROWSER_PATH=/path/to/chromium npm run check
```

`npm test` includes **every** `tests/**/*.test.ts`, including integration tests. Tests are never silently skipped because a browser is missing; browser setup must work. `npm run typecheck` checks source and every test/helper through `tsconfig.tests.json`. `check` runs build, full typecheck, all tests, and a fresh packed-package installation smoke. The current lockfile has the private root plus seven package importers. Workspace source links are explicit; shipped manifests use matching concrete versions. There are no Guidepup, model SDK, pixelmatch or pngjs dependencies. The package smoke independently installs every package with only its declared local tarball dependency closure; `npm run test:source` repeats the aggregate check from a fresh source extraction.

## Intentional contract changes

- Default policy inputs contain only actual screen-reader output; synthetic labels, DOM-assisted speech and verifier hints are not reconstructed
- No built-in LLM, provider credentials, mandatory configuration file, prompt repository, planner/reflection scheduler, or Guidepup capability generator remains
- Screenshot keyboard behavior is explicitly deprecated, functional, and included under `rawstep/legacy`; screenshot diff/provider prompt machinery is removed
- Task verification is independent of a policy success claim. Analysis is post-run and cannot change the recorded outcome
- Static reports prioritize escaped immutable evidence and stable event references; exact legacy interactive panel markup is not an API

See [source editing map](./editing-map.md), [migration contracts](./migration.md) and the final [verification record](./verification.md) for current aggregate results.

Later addition: first-class screenshot model exploration is now in `src/screenshot/`, separately from the historical compatibility mappings above. See [screenshot verification](./screenshot-verification.md).
