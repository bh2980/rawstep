# VoiceOver 발화·문맥 감사 — 2026-10-15

## 목표와 현재 구현의 차이

목표는 Rawstep이 전달하는 읽을 요소·현재 상태·이전 요소와 행동·구조적 문맥으로 VoiceOver의 발화를 재현하는 것이다. Rawstep의 이동을 대신 구현하는 것은 발화 엔진의 완료 조건이 아니다. Native 수집에서 이동 명령을 사용하는 이유는 발화 조건을 만들기 위해서다. 서로 다른 요소에 도착한 기록은 같은 입력에 대한 발화 비교로 취급할 수 없다.

현재 구현에는 실제로 문맥별 발화 규칙이 있다. 다만 그 규칙의 상당 부분이 브라우저 탐색 백엔드에 결합되어 있다. 공개된 순수 함수 `formatSimulatedSpeech(node, checkedStateChanged, sourceCommand)`만으로는 이전 컨테이너·표 위치·반복·지연 힌트를 모두 재현하지 못한다. 따라서 현재 결과를 독립적인 문맥 기반 발화 엔진이 완성된 것으로 보고할 수 없다.

## 문맥 발화를 계측하고 적용한 실제 부분

- **컨테이너 진입·재진입:** `context-return-v1`의 6개 대조 시나리오를 Safari와 Chrome에서 각각 36동작 관측했다. 안쪽 그룹에서 바깥 region으로 이동하거나 다시 들어올 때 문맥이 재발화되는 것을 확인했다. 예를 들어 `Save preferences button Account preferences region`은 안쪽 그룹에서 나올 때와 외부 마커에서 돌아올 때 모두 관측됐다. 백엔드 `announce()`의 `announcedFocusContext`와 `announcedContainers`가 이 이력을 사용한다.
- **표 문맥:** 백엔드는 이전 셀·열을 `announcedCell`, `announcedColumn`으로 보존해 행·열·헤더 안내를 조절한다. 구현 존재가 모든 표 조합의 검증 완료를 뜻하지는 않는다.
- **상태·명령:** 순수 포매터는 현재 상태뿐 아니라 체크 상태 변경 여부와 명령을 받는다. 활성화·편집·비동기 발화 처리는 백엔드에도 분산되어 있다.
- **힌트와 반복:** `hintTarget`과 지연 힌트 상태를 사용한다. 현재 600ms 구현값을 VoiceOver 전체 환경의 보편적인 타이밍 규칙으로 간주할 근거는 없다.

직접 확인한 원본은 `data/runs/context-return-v1-2026-10-15T02-53-00-887Z`와 `data/runs/context-return-v1-2026-10-15T02-57-56-840Z`다. 공통 입력 SHA-256은 `143fef05d8f6451d8d3dfe22b87def3b2a8a43811ffb3b83e3c89b45f3c79638`이다. 이 사례들은 이미 보정에 사용했으므로 독립 평가 자료가 아니다.

## 아직 부족한 부분과 이후 작업의 경계

Chrome의 이름 없는 article 안내, 목록 안팎의 위치 안내, summary 활성화의 반복 발화, readonly 텍스트 표현 등 기존 불일치가 남아 있다. 동일 대상·동일 상태인지 먼저 확인한 뒤 발화 규칙의 실패로 분류해야 한다. 특히 다른 요소로 이동한 비교 결과를 문구 규칙 보정에 사용해서는 안 된다.

필요한 다음 변경은 새 이동 엔진이 아니라, 기존 문맥 규칙을 외부 입력으로 호출할 수 있게 하는 최소한의 분리다. 먼저 기존 규칙이 요구하는 이전 컨테이너·표 위치·상태 변화·명령·반복 이력을 명시해야 한다. 실제 관측 발화와 사후 정답은 예측 입력에 넣지 않는다. 문맥 입력이 확인되지 않은 기존 자료는 불확실성을 유지한다.

이번 감사에서는 API 분리나 추가 수집까지 진행하지 않았다. 탐색 성능을 발화 엔진 성능으로 보고하지 않으며, 현재 지원 범위와 정확도는 문맥별 발화 근거로 다시 판단해야 한다.


## 감사 이후 적용한 변경

`formatVoiceOverSpeech(input, previousContext)`를 추가하여 위의 컨테이너·표·포커스 진입 및 Chrome 표 편집 문맥 규칙을 순수 함수로 옮겼다. 반환값은 `speech`, `usageHint` 후보, 다음 `context`다. 기존 브라우저 백엔드도 같은 함수를 사용한다. 이전 코드의 `announcedContainers`, `announcedFocusContext`, `announcedCell`, `announcedColumn`은 이제 전달 가능한 `VoiceOverSpeechContext`의 필드다.

Native의 관측 대상과 공유 HTML로만 입력을 구성한 브라우저 없는 회귀 테스트에서 Safari 36/36, Chrome 32/36 Main Speech가 일치한다. Chrome의 알려진 article 이름 불일치 4건도 테스트에서 계속 계산한다. 원본 발화는 정답 비교에만 사용하며 함수 입력에 전달하지 않는다. 이 사례들은 독립 평가가 아니다. 지연 힌트의 스케줄링·취소, 활성화의 침묵·반복, live-region 및 문자 편집 이벤트 순서는 아직 백엔드에 남아 있다.


검증: 빌드와 타입 검사 통과. 단위 테스트 1,236개 통과·1개 기존 skip, 관련 브라우저 회귀 71개 통과. 최종 빌드의 편집·포커스 관련 25개를 추가 확인했다(나머지 34개는 이름 필터로 미실행). 격리된 임시 프로젝트에 tarball만 설치한 검사에서 공개 API, 루트·하위 경로의 동일 함수, 소비자 타입 선언, 브라우저 없는 양쪽 프로파일 예제를 확인했다. 새 Native 수집이나 독립 일반화 평가는 이번 변경에 포함하지 않았다.
