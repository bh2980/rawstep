# 문맥 기반 발화 엔진 독립 평가 — 2026-10-15

Rawstep이 읽을 대상과 상태를 제공하는 `formatVoiceOverSpeech`를 평가했다. 이동 엔진을 평가하거나 확장하지 않았다. Native 수집 명령은 발화 조건을 만들기 위한 외부 입력이다.

| 지표 | Safari + VoiceOver | Chrome + VoiceOver |
| --- | ---: | ---: |
| 계획 / Native 관측 완료 동작 | 60 / 60 | 60 / 60 |
| 현재 대상·상태·상위 문맥 입력 확인 | 60 / 60 | 60 / 60 |
| 이전 문맥·명령·발화 수신 창까지 비교 가능한 동작 | 60 / 60 | 60 / 60 |
| Main Speech Exact, 정규화 후 | 60 / 60 | 60 / 60 |
| 전체 발화 후보 원문 일치 | 0 / 60 | 0 / 60 |
| 힌트 후보, 정규화 후 | 60 / 60 | 60 / 60 |

Main Speech의 조건부 일치율과 전체 계획 대비 일치율은 모두 100%다. 모든 동작에서 Native의 발화 요청은 본문과 힌트 2건이었다. 두 요청의 순서를 유지하며 구두점을 정규화하면 60/60씩 일치한다. 원문 차이는 포매터가 본문 조각 사이에 넣은 쉼표다. 예를 들어 Native는 `Check booking button`, 엔진은 `Check booking, button`을 반환했다. 원문 일치율 0%를 정규화 지표로 덮어쓰지 않는다. 요소 이름·설명·값 자체에 있는 구두점을 지우는 전역 치환으로 고쳐서는 안 된다.

이 실험은 발화 후보를 비교한다. 힌트의 지연·취소, 비동기 발화 큐의 동작까지 재현했다고 주장하지 않는다. Navigation Accuracy, 시뮬레이터 State Accuracy, Task Success는 이 발화 전용 실험에서 평가하지 않았다. Native 상태 확인은 발화 **입력** 확인이며 시뮬레이터의 상태 전이 정확도가 아니다.

## 무엇을 새로 확인했는가

공유 HTML 6개와 10동작씩의 순서를 만들었다. 같은 템플릿과 대조쌍은 모두 같은 평가 그룹에 두었고, 이전 780개 사례 정의(복사본 포함)와 그룹 ID 및 정확한 명령 시퀀스의 겹침이 없음을 수집 전에 확인했다. 세 대조쌍은 다음과 같다.

- 이름 있는 main 안의 형제 region: 두 버튼을 감싼 그룹의 유무만 달리했다. 동일한 버튼의 발화가 그룹/region 진입 이력에 따라 달라졌다. 10단계 중 0·3·7·9에서 문맥 발화가 달랐다.
- region → 이름 있는 form → fieldset 또는 ARIA group: 체크 안 된/된 체크박스와 그룹 바깥 버튼을 오갔다. 두 그룹 구현의 Native 발화는 모든 단계에서 같았다.
- region → 이름 있는 article → 표: 2열과 3열 표에서 같은 버튼들을 오갔다. 문맥에 다시 진입하는 0·3·7·9단계의 열 수 안내가 달랐다.

이 코호트에서는 Safari와 Chrome의 Native 발화 요청 문자열·순서가 60/60 동작에서 같았다(수신 시각 제외). 전체 AX 트리가 같다는 뜻은 아니다. 새로 만든 세 조합에서 기존 문맥 규칙이 통했다는 근거이며, 무작위 사이트나 모든 UI에서 100%라는 근거는 아니다. Chrome의 이름 없는 article 등 이전에 남긴 실패도 해소된 것이 아니다.

## 입력과 원본 보존

모델과 발화 입력, 양쪽 프로파일의 예측을 Native 수집 전에 고정했다. 원본 AX·발화·시각과 첫 평가 결과는 수정하지 않았다. 관측 후에는 이 코호트를 `inspected-regression`으로 기록했다. 이후 이 자료로 보정한 결과는 독립 평가와 구분해야 한다.

- 사례 입력 SHA-256: `a39904cd966434cc5ad4c4d91a349b6eeb5e2332974fcab4321182b1c4bda3a8`
- 발화 입력 SHA-256: `45138e042822b5d5676e849dbf5682dfdc7337f41de352f5197db6df633bb5ca`
- 실행한 전체 JS 빌드 SHA-256: `b61dea8568e8252bf7a89aa8b4c767de13391a2875859ed569ce90c66dcdf287`
- macOS 26.6.2 / Safari 26.6.2 / Chrome 155.0.8059.80, 영어 발화, `baseline-v2-dnd`.

현재 대상은 키보드 포커스로 추정하지 않았다. 기존의 독립적인 VO 윤곽 관측과 Native AX 기하 정보가 안정적인 단일 후보를 지목하는지 확인하고, 그 후보의 역할·이름·체크 상태·상위 문맥을 대조했다. 이는 직접적인 논리 읽기 커서 API가 아니며 Navigation Accuracy 점수가 아니다. 요청/응답·발화 수신·AX 관측 시각도 보존했지만, 유한한 수신 창이 발화 완료를 보장하지는 않는다.

작성한 입력 주석과 Native 원천 관측은 별개다. 이 실험에서 사용하지 않는 `containers[].items`와 셀 좌표·헤더·span 주석은 Native 입력 확인 범위에 넣지 않았다. 향후 학습용으로 사용할 때 이 필드를 관측된 정답으로 간주하면 안 된다. 공개 축약본에는 전체 AX와 원본 이미지 대신 원본 해시 및 파생된 입력 확인 결과가 들어 있다. 전체 원본은 기존 로컬 수집 아카이브에 남아 있다.

평가기의 최초 실행은 JSON 저장 시 사라지는 `undefined` 선택 필드 때문에 모델 재실행 확인에서 중단됐다. 같은 JSON 직렬화를 적용하도록 수정한 내역을 별도로 남겼다. 모델·입력·저장된 예측·평가 자격 조건은 바꾸지 않았다.

## 재실행

공개 [회귀 자료](../tests/fixtures/voiceover-evidence/native-speech-contexts-2026-10-15.json)는 공유 HTML·명령·예측 입력을 한 번만 보존하고, Native 관측과 품질 정보를 브라우저별로 분리한다. 브라우저나 VM 없이 다음 테스트를 실행할 수 있다.

```sh
npm run build
npx vitest run tests/mock-voiceover-speech-transfer.test.ts
```

새 Native 실행은 기존 `packages/vo-corpus/src/collect.ts`를 사용한다. 이번 실행의 입력과 모델이 고정된 로컬 아카이브를 다시 평가하는 명령은 다음과 같다(`packages/vo-corpus`에서 실행, 출력 디렉터리는 새 이름 사용).

```sh
node --import tsx src/evaluate-speech.ts \
  data/analyses/speech-contexts-v1-pre-observation \
  data/runs/speech-contexts-v1-2026-10-15T04-13-28-494Z \
  data/analyses/speech-contexts-v1-safari-recheck
```

Chrome 원본은 `speech-contexts-v1-2026-10-15T04-17-26-062Z`다. 원본, 고정한 모델 JS와 예측, 첫 보고서, 노출 이력은 로컬 `packages/vo-corpus/data/` 아래에 있다. 위 로컬 명령은 해당 아카이브가 있어야 하며 새 클론에는 공개 축약본과 브라우저 없는 회귀 테스트가 제공된다.

검증: 전체 타입 검사 및 수집 도구 타입 검사 통과. 전체 단위 테스트 1,239개 통과·1개 기존 skip, 수집·입력 확인·분모 관련 테스트 6개 통과. 실제 Native 실행은 브라우저별 6/6 시작 정렬 및 60/60 동작 관측 완료다. 기존 발화 엔진은 이번 평가 과정에서 수정하지 않았다.
