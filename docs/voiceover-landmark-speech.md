# Landmark speech on focus entry and return

The inspected eBay sample exposed an unnamed-banner omission. The Native input builder and verifier discarded the exposed role when its name was empty; the speech formatter also ignored an explicitly supplied unnamed landmark. The [live-page audit](./voiceover-target-conditioned-evaluation.md) keeps those collection and input failures separate from speech accuracy. This reduction tests the wording rule using controlled caller inputs, rather than changing simulator movement.

Six conditions share the same two buttons and focus sequence: unnamed banner/navigation/main/complementary/contentinfo and a named-banner contrast. Tab enters the first button, moves to the second, and leaves the landmark; Shift+Tab returns to the second, then the first. Both Native browser profiles completed all 30 planned actions, with per-action AX/visible-cursor captures. Inputs and v16/v10 model predictions were frozen before either profile ran. These are calibration scenarios derived from an inspected failure; they are now regression tests.

The [immutable Native fixture](../tests/fixtures/voiceover-evidence/native-landmark-speech-2026-10-15.json) retains the first predictions/results, raw receipts, input hashes and Native target/ancestor evidence. The separate [evaluation audit](../packages/vo-corpus/test/landmark-speech-evaluation.json) records the verifier correction and regression without replacing first scores. The original plan inherited an inaccurate prose description of listen bounds; the actual archived cases use minimum 2000 ms, quiet 1200 ms and maximum 7500 ms, and retain per-command receipt/AX times. Quiet windows do not prove synthesis completion.

The observed rule is nearest-landmark focus context: entering or reentering the exposed landmark appends its optional name and role; another focus move within it does not repeat the suffix. Leaving it clears that focus context. Empty names do not erase a Native-exposed landmark role. The existing formatter now preserves this history using caller-owned container IDs; no element name, URL or HTML shape is hardcoded. Named-group, article and table behavior remains covered by the existing regression suites.

Safari and Chrome share `AXLandmarkContentInfo` semantics but expose and speak different labels: **content information** in the observed Safari profile and **footer** in Chrome. The Native verifier identifies the common role from the subrole. The formatter keeps the two spoken labels in their independent reference profiles. The current profiles are Safari `english-dom-navigation-evidence-v17` and Chrome `english-chrome-navigation-evidence-v11`; historical profile aliases remain available. Native viewport sizes differed, but these fixed, nonresponsive pages exposed the same target/state/container inputs; no claim of universally identical browser settings or versions is made.

The verified scope here is ordinary button **Tab and Shift+Tab** entry, within-region movement, exit and return in those five landmark roles. The source site used an image-link, so that exact production composition still needs an independent follow-up after correction. New sites, nested/mixed landmarks, dialogs, frames and all other VoiceOver commands are not validated by these 60 actions. The 100% regression score does not establish 90% real-site accuracy, Navigation Accuracy, State Accuracy or Task Success.

Reproduce through the existing generator/collector with `--set landmark-speech-v1` and a fresh `--out data/cases/landmark-speech-v1-recheck`, then collect that directory separately with `--browser safari` and `--browser chrome`. See the [Native setup commands](./voiceover-target-conditioned-evaluation.md). Browser-free regression runs with `npm test -- tests/mock-voiceover-landmark-speech.test.ts`; corpus source/HTML checks run with `node --import tsx --test packages/vo-corpus/test/landmark-speech.test.ts` from the repository root.
