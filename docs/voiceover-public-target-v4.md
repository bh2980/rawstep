# 새 사이트 발화 평가와 입력 감사 — 2026-10-16

이번 결과는 발화 엔진의 일반 웹 정확도나 실사용 완료를 입증하지 않는다. 새로운 사이트 4곳의 계획된 반환 동작은 두 브라우저에서 모두 관측했지만, 이전 문맥·읽기 위치·복합 역할 입력을 확인하지 못한 동작이 많다. 비교 가능한 본문은 대부분 맞았으며, 전체 발화에서는 힌트 차이가 남았다. 다음 개발은 수집량 확대보다 실제 Rawstep 입력과 복합 역할, 힌트 문맥 확인에 집중한다.

Safari가 끝난 뒤에도 Chrome 종료 전까지 결과를 분석하거나 소스를 변경하지 않았다. 실행 JS SHA-256은 `2276852e5c82fc5528c717074422fe02e31e5967ac42cdaca092cf0be4f14f9e`, 프로파일은 Safari v24 / Chrome v18이다. 기준 커밋은 `e16f413`이며, 기존 미커밋 평가 진단이 있는 수집 작업 트리의 소스·실행 빌드 해시를 보존했다. 깨끗한 커밋 빌드라고 주장하지 않는다.

## 복합 역할 입력 누락

Chrome의 본문 불일치 1건에는 링크 안의 제목이 있었다. Native AX에 제목 역할·수준이 보존돼 있지만 관측 입력은 주 역할인 링크만 전달했고, 검증기도 이를 동등하다고 잘못 인정했다. 발화 엔진에는 기존 복합 제목/링크 표현이 이미 있다. 이 관측으로 새 발화 규칙이 필요하다고 결론 내릴 수 없다.

`nativeSpeechInput`과 `checkSpeechInput`은 이제 링크 내부/상위의 제목, 제목 내부 링크, 아직 이 검증기가 확인하지 않는 복합 제목 메타데이터를 **미계측**으로 보고한다. 단순 주 역할만 비교해서 복합 읽기 단위를 동등하다고 인정하지 않는다. Native 복합 역할을 기존 Rawstep 표현과 독립적으로 연결하는 검증은 다음 작업이다. 일반 엔진의 해당 기능을 삭제하거나 미지원으로 바꾼 것은 아니다.

## 실제로 남은 문제

- **현재 입력 범위:** 양쪽 브라우저에서 각각 한 슬롯의 조상 구조를 확인하지 못했다. 추가로 Safari 2건·Chrome 2건은 반환 후 윤곽과 AX를 단일 대상에 연결할 수 없었다. Chrome의 복합 링크/제목 1건도 이제 미계측이다.
- **이전 문맥:** 첫 평가기의 이전 문맥 미확인 이슈는 Safari 7건·Chrome 4건이다. 다른 이슈와 겹칠 수 있다. 윤곽 누락·불일치, 같은 사각형의 그룹/링크/텍스트, 구조 경계가 포함된다. 발화나 키보드 포커스로 빈 위치를 채우지 않았다.
- **힌트:** 비교 가능한 Full 실패는 브라우저마다 4건으로 모두 weather.gov에서 나왔다. 이름과 같은 help의 반복 여부, 이름 없는 form 안 버튼의 웹 영역 안내, Chrome 링크의 웹 영역 종료 안내가 예측과 달랐다. 단일 사이트의 네 동작은 일반 규칙의 충분한 대조군이 아니다. 원문을 덮어쓰거나 힌트를 빼서 Full 점수를 높이지 않는다. 제목/help 일치 여부와 명명된/이름 없는 form을 분리한 최소 대조가 필요하다.
- **Rawstep 통합:** 이번 예측 입력은 Native AX에서 구성했다. Chromium 기반 Rawstep이 같은 의미 입력·이전 문맥을 제공하는지는 별도 검증해야 한다. 기존 작성 과업의 통합 회귀가 이번 실제 사이트의 입력 동등성을 대신하지 않는다.

이 실험은 목표가 외부에서 선택된 발화 후보를 평가한다. Navigation Accuracy, 시뮬레이터 State Accuracy, Task Success는 측정하지 않았다. 독립적인 윤곽/AX 연결은 위치 관측의 품질이며 직접적인 논리 읽기 커서 API가 아니다. 유한 수신 창은 힌트의 귀속·완료·취소·타이밍 동등성을 보장하지 않는다.

## 원본과 메타데이터

원본 발화·AX·준비 동작·수신/요청/관측 시각·첫 예측은 로컬 `packages/vo-corpus/data/analyses/public-named-target-v4/`에 보존했다. 공개 감사에는 URL, 수치, 품질 분류와 해시만 포함하고 웹사이트의 요소 이름·발화·AX 내용·예측 입력은 포함하지 않았다. 현재 네 사이트는 확인한 회귀 자료이며 향후 새 사이트 평가에서 제외한다.

원래 페이지 텍스트 지문은 `nativeAccessibleText`에 AX 루트 대신 덤프 전체를 전달해 빈 문자열 해시가 됐다. 원래 값은 변경하지 않고 저장된 루트에서 별도 지문을 계산했다. 이 필드는 선택·예측·게이트·점수에 쓰이지 않았다. 파생 AX 텍스트 지문도 HTML/DOM 동일성이나 브라우저 차이의 원인을 입증하지 않는다.

감사 도구의 첫 실행은 메모리의 선택 필드 `undefined`와 JSON에서 생략된 필드 차이로 멈췄다. JSON 직렬화 기준으로 비교하도록 고친 뒤 첫 평가와 모든 점수를 재현했다. 입력·예측·게이트·원천 관측을 바꾸지 않았다.

공개 자료의 선택 재현, 분모, 첫 점수 보존, 복합 역할 게이트, 지문 정정과 비공개 필드 제외를 확인하는 명령:

```sh
cd packages/vo-corpus
node --import tsx --test test/public-named-target-v4.test.ts test/speech-input.test.ts test/speech-evaluation.test.ts
```

이는 보존 자료와 입력 검증 코드의 회귀 검사다. 라이브 사이트를 다시 방문하거나 새 Native 정확도를 측정하지 않는다.
