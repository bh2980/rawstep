# 발화 구분자 보정 — Safari v10 / Chrome v4

`formatVoiceOverSpeech`가 발화 조각 사이에 넣던 쉼표를 공백으로 바꿨다. 이름·설명·값 안의 문자는 그대로 전달하며, 표의 `2 columns, 3 rows`처럼 관측된 문법의 쉼표도 유지한다. 전역 문자열 치환은 사용하지 않는다. 저수준 `formatSimulatedSpeech`는 기존 쉼표 구분자를 기본값으로 유지하고 선택적인 네 번째 인자로 조각 구분자를 받는다. 관측과 달랐던 `URL field`의 대문자 표기도 수정했다.

출력 바이트가 달라지므로 Safari 프로파일은 `english-dom-navigation-evidence-v10`, Chrome은 `english-chrome-navigation-evidence-v4`로 올렸다. 이전 프로파일 ID에 대한 증거 조회는 유지한다. 이동 동작은 변경하지 않았다.

## 기존 자료 재생: 회귀 결과

| 자료 | 보정 전 | 보정 후 | 범위 |
| --- | ---: | ---: | --- |
| Safari 문맥 조합, 원문 전체 후보 시퀀스 | 0/60 | 60/60 | 기존에 확인한 자료의 회귀 |
| Chrome 문맥 조합, 원문 전체 후보 시퀀스 | 0/60 | 60/60 | 기존에 확인한 자료의 회귀 |
| 기존 Safari 단일 본문 기록, 원문 | — | 45/50 | 수동 의미 주석으로 재생한 진단값 |
| 같은 50건, 공백만 접은 구두점·대소문자·순서 | — | 50/50 | 원문 일치율과 구분 |

50건 중 5건에는 Native 요청의 앞뒤 공백이나 연속 공백 차이가 남는다. 현재 페이지 링크와 링크를 포함한 제목이 해당한다. 관측된 공백을 임의로 삽입하는 규칙은 추가하지 않았다. 이 50건의 의미 입력은 과거의 수동 추상화이며, Native AX 입력 동등성이 입증된 정확도 벤치마크가 아니다.

문맥 조합 120건은 본문과 힌트의 두 요청을 **정규화하지 않고 배열 순서대로** 비교한다. 첫 독립 평가 결과와 Native 원본은 바꾸지 않았으며, 새 엔진의 결과는 회귀로 분리했다. 힌트 스케줄러·취소·네이티브 큐 시간까지 재현했다는 뜻은 아니다.

## 원문 구두점 추가 확인

쉼표·마침표·날짜가 들어 있는 이름, 쉼표가 들어 있는 설명을 가진 작은 페이지를 새로 만들었다. 각 브라우저에 같은 6동작을 실행했다. 입력·예측·JS 빌드는 Native 수집 전에 고정했다. 이는 보정을 확인하는 목적의 실험이며 독립 일반화 점수가 아니다.

| 항목 | Safari | Chrome |
| --- | ---: | ---: |
| 고유 계획 / Native 동작 완료 | 6 / 6 | 6 / 6 |
| 기본 대상·상태·문맥 확인 | 6 / 6 | 6 / 6 |
| 설명까지 확인된 비교 가능 입력 | 4 / 6 | 4 / 6 |
| 해당 입력의 원문 전체 후보 일치 | 4 / 4 | 4 / 4 |
| 고유 계획 전체 대비 확인된 일치 | 4 / 6 | 4 / 6 |
| 설명 입력 미계측 | 2 / 6 | 2 / 6 |

예를 들어 `Save, review, and close. button`, `Reports, weekly. checked checkbox`의 원문 구두점이 보존됐다. 설명이 있는 버튼의 4개 관측은 `AXHelp`로 설명을 확인한다는 사전 조건을 충족하지 못했다. 현재 덤프의 `AXDescription`과 `AXHelp`에는 그 설명이 없었다. 본문은 진단상 일치했지만, Native에는 추가 콘텐츠 메뉴 안내가 더 있었다. 이 관측은 성공에서 제외하고 계획 분모에 남겼다. 실제 추가 콘텐츠의 존재를 독립 관측한 뒤 힌트 규칙을 검증해야 한다.

### 수집 실패도 보존

가상머신이 중지되어 있었고 직접 네트워크 연결도 복구해야 했다. Chrome에서는 복구 창을 감지한 안전장치가 실험 키 입력을 막았다. 별도의 준비 단계에서 정확한 Close 버튼으로 복구 창을 닫은 뒤 다시 수집했다.

총 7회 시도 중 시작 실패 5회(가상머신 중지 1, 연결 실패 2, Chrome 복구 창 2)를 보존했다. 재시도까지 펼친 동작 분모는 42, Native 동작 관측은 12다. 이 분모에서 확인된 발화 일치는 8/42다. 고유한 12개 계획 동작은 최종적으로 모두 관측했지만, 이는 전체 시도의 수집 성공률과 다르다. 처음 실패한 디렉터리·입력 아카이브와 최종 Native 기록을 덮어쓰지 않았다.

공개 축약 자료에는 공유 HTML·행동·입력, 브라우저별 실제 발화와 품질, 원본 AX 해시, 시도별 실패를 남겼다. 전체 AX와 VO 윤곽 이미지 및 명령/응답/발화 시각은 기존 로컬 아카이브에 있다. VO 윤곽의 안정적인 단일 기하 후보를 이용했으며 키보드 포커스를 읽기 커서로 대체하지 않았다. 유한한 수신 창은 Native 발화 완료를 보장하지 않는다.

## 재실행과 증거

저장소 체크아웃에서 실행한다.

```sh
npm run build
npx vitest run tests/mock-voiceover-punctuation.test.ts tests/mock-voiceover-speech-transfer.test.ts
```

- [기존 문맥 조합의 첫 평가](./voiceover-speech-context-evaluation.md)
- [구두점 보존 Native 자료](https://github.com/bh2980/rawstep/blob/claude/voiceover-speech-pattern-collection-5ba5cc/tests/fixtures/voiceover-evidence/native-speech-content-2026-10-15.json)
- 로컬 회귀 보고서: `packages/vo-corpus/data/analyses/speech-separators-v10-v4-regression/report.json`
- 추가 확인 입력 SHA-256: `2e6461674bbea20568732d04303767c9224e24ddd5e8be11e1279c3b9fdd0ad4`
- 추가 확인 및 회귀에 고정한 JS 빌드 SHA-256: `7135faff19cebc4d2155d1e1e009c2cceba6dc2c5aaeb59736138a607a3e8ddb`

이 보정으로 새 UI 전체의 정확도나 Native VoiceOver 대체 가능성을 단정하지 않는다. 이전 Chrome의 이름 없는 article 문맥 불일치, 이번 설명/추가 콘텐츠 힌트, 일부 원문 공백 및 비동기 큐 동작이 남아 있다.

검증: 빌드·타입 검사, 관련 브라우저 회귀 및 격리된 패키지 설치 검사가 통과했다. 설치한 패키지에서 양쪽 프로파일의 브라우저 없는 발화 예제와 타입 선언도 확인했다. Native 보존 자료는 수정하지 않았다.
